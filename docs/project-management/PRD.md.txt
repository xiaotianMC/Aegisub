# Aeg 项目管理与视频字幕工作台
## 产品需求规格说明书（PRD）

文档版本： 1.0  
状态： 需求访谈完成，待技术勘察  
产品基础： 基于自定义修改版 Aegisub（以下简称 Aeg）开发  
目标平台： Windows 优先，架构兼顾跨平台  
发布形式： GitHub 源码、Windows 安装版、Windows 便携版

---

# 1. 产品概述

## 1.1 产品定位

在现有修改版 Aeg 的基础上，增加一套完整的项目管理和视频素材工作流，使 Aeg 从字幕编辑器扩展为面向视频字幕制作的项目工作台。

产品应保留现有字幕编辑器的核心能力，并提供独立的项目管理入口，支持创建和管理多个项目、系列项目、视频素材、字幕文件、下载任务及项目配置。

用户能够从项目创建开始，完成视频获取、素材归档、字幕编辑和项目状态管理，减少在 Aeg、文件资源管理器、下载工具之间反复切换的操作。

## 1.2 产品目标

1. 建立独立、完整的项目管理页面。
2. 支持单视频项目与系列项目，所有项目对应真实磁盘目录。
3. 集成 yt-dlp，支持视频下载、任务队列和自动归档。
4. 使项目管理、文件浏览和原有字幕编辑器形成连续工作流。
5. 提供文件监测、项目迁移、备份和异常恢复能力。
6. 保护原有 Aeg 功能、字幕文件和用户项目数据。
7. 提供安装版和便携版，并建立适合自定义 Aeg 分支的更新机制。
8. 不引入未经用户明确同意的遥测或自动数据上传。

## 1.3 设计原则

- 项目优先： 所有素材和任务都能明确关联到项目。
- 真实目录： 项目对应磁盘上的真实文件夹，而不是仅存在于应用内部的虚拟记录。
- 配置可迁移： 项目配置跟随项目目录。
- 数据安全优先： 不静默覆盖或删除用户文件。
- 后台任务化： 下载、文件扫描和缩略图生成不能阻塞编辑器界面。
- 兼容优先： 修改现有核心前先完成影响分析并确认方案。
- 可维护： 尽量复用现有能力，避免不必要的常驻服务和依赖。
- 不预设技术： 具体 UI、数据存储及集成方案由仓库勘察后决定。

# 2. 用户与使用场景

## 2.1 目标用户

主要面向需要长期处理视频、字幕、翻译稿和成片素材的个人创作者，也兼顾未来的系列化制作需求。

## 2.2 核心使用场景

### 场景 A：开始一个新视频项目

用户启动 Aeg，进入项目首页，创建项目并指定存储目录。系统生成默认目录结构，用户导入本地视频或创建下载任务。

### 场景 B：制作一个系列

用户创建系列项目，在系列页面添加各集子项目。每集有独立状态、素材目录和字幕工程，系列页面统一展示集数及整体进度。

### 场景 C：下载视频并自动归档

用户从项目页面或全局下载中心提交视频网址。系统调用 yt-dlp 下载，完成后按照项目归档规则整理文件、注册素材，并询问用户是否打开 Aeg 编辑字幕。

### 场景 D：继续之前的工作

用户重新启动软件，首页突出显示上次使用的项目和未完成任务。系统检查项目目录、任务状态和现有文件后，恢复可恢复的工作。

### 场景 E：迁移项目

用户将项目文件夹移动到其他磁盘或电脑。Aeg 检测原路径失效，允许用户重新指定目录，并恢复项目关联。

# 3. 信息架构与页面设计

## 3.1 全局导航

采用左侧导航、卡片式首页和详细项目工作区的组合结构。

建议导航包括：

- 首页
- 所有项目
- 系列项目
- 下载中心
- 最近打开
- 模板管理
- 设置

全局搜索覆盖项目、系列、文件和下载任务。

以上为产品层面的导航建议，实际页面实现应结合现有 Aeg UI 框架进行技术评估。

## 3.2 项目首页

项目首页负责展示项目列表、最近使用的项目及未完成任务。

每张项目卡片至少展示：

- 项目名称
- 项目状态
- 封面
- 最近更新时间
- 项目文件夹路径

首页应支持创建项目、导入已有文件夹、打开项目、搜索及筛选。

## 3.3 项目仪表盘

项目工作区以仪表盘为主，展示：

- 项目元数据
- 项目状态和状态建议
- 最近文件
- 视频素材
- 字幕文件
- 下载任务
- 快速打开编辑器的入口
- 项目目录及相关操作

具体卡片布局、排序方式和交互细节可以在技术勘察后进一步设计。

## 3.4 文件管理器

项目内部提供完整文件管理器，支持：

- 文件和目录浏览
- 多选
- 批量操作
- 新建文件夹
- 重命名
- 移动和复制
- 删除
- 拖拽导入
- 搜索与排序
- 在系统文件资源管理器中打开目录

涉及覆盖、删除或其他可能造成数据丢失的操作时，必须根据操作类型提供确认机制。

## 3.5 编辑器联动

默认在同一窗口中切换项目管理页面和原有字幕编辑器，同时允许独立编辑窗口。

打开项目中的字幕文件时，应尽可能复用现有 Aeg 编辑能力，不得擅自改变 ASS 等字幕格式的读写行为。

第一版项目列表管理多个项目即可；不要求同时在多个项目中编辑字幕。

# 4. 项目与系列管理

## 4.1 项目类型

支持两种类型：

1. 独立项目：对应一个视频或一个完整制作任务。
2. 系列项目：包含多个按集管理的独立子项目。

系列页面以集数列表为主要形式，支持查看每集状态、打开子项目及查看系列整体进度。

## 4.2 创建和导入

支持：

- 新建项目并自动创建目录。
- 注册已有文件夹作为项目。
- 创建系列项目并添加子项目。
- 为项目设置名称、描述、来源、语言、标签及负责人。

注册已有文件夹时，不得默认移动或复制其中的现有文件。

## 4.3 项目元数据

项目需要记录：

| 字段 | 说明 |
|---|---|
| ID | 稳定的项目标识 |
| 名称 | 项目显示名称 |
| 描述 | 项目简介或备注 |
| 来源 | 来源网址、视频 ID 等 |
| 语言 | 原语言和目标语言 |
| 标签 | 用户自定义分类 |
| 负责人 | 项目负责人信息 |
| 状态 | 当前制作状态 |
| 封面 | 项目封面引用 |
| 路径 | 项目根目录 |
| 创建时间 | 项目创建时间 |
| 更新时间 | 最近更新时间 |
| 历史 | 项目操作历史 |

项目 ID 应尽可能稳定，避免仅依赖路径作为项目唯一标识。

## 4.4 项目状态

支持以下状态：

- todo：待开始
- doing：进行中
- review：待校对
- done：已完成
- paused：已暂停

状态由用户手动管理为主。系统可以根据下载、编辑或导出等事件给出状态建议，但不得仅因为文件存在或下载成功就自动认定字幕制作完成。

## 4.5 目录模板

支持：

- 默认目录模板。
- 用户自定义模板。
- 项目级目录配置。
- 模板导入、导出和分享。
- 创建项目时应用模板。

模板修改原则：

- 修改全局模板默认只影响新建项目。
- 已有项目不应因为模板更新而被自动移动或重命名。
- 项目目录调整必须经过明确操作，并处理目标路径冲突。

建议的默认目录结构可以包含视频素材、字幕文件、翻译稿、音频和导出成品，但最终目录名称与模板格式待确认。

# 5. 文件监测、移动与冲突处理

## 5.1 外部文件变化

Aeg 应监测项目目录中的文件变化，包括新增、删除、重命名和修改，并及时更新文件列表。

文件监测应在后台运行，不能阻塞编辑器。

## 5.2 项目移动

支持：

1. 在 Aeg 内主动移动项目。
2. 检测外部移动或重命名导致的路径失效。
3. 允许用户重新指定新目录。
4. 重新校验项目配置和文件关联。
5. 正确处理系列父目录与各集子项目的路径关系。

项目移动不应导致字幕工程丢失，也不得未经确认修改项目外部的文件。

## 5.3 冲突保护

以下情况应进入安全处理流程：

- 文件正在下载时被移动或删除。
- 字幕文件正在编辑时被外部重命名。
- 目标路径存在同名文件。
- 文件正在被其他进程占用。
- 项目配置与实际磁盘目录不一致。

系统应优先刷新和核实状态。涉及覆盖、删除或无法自动安全处理的冲突时，暂停危险操作并提示用户确认。

不得静默覆盖用户文件。

# 6. 视频下载系统

## 6.1 下载引擎

采用 yt-dlp 作为独立子进程运行。

Aeg 负责任务队列、项目关联、任务状态、进度展示、失败重试和归档；yt-dlp 负责实际下载执行。

具体进程控制方式、输出解析和依赖分发方案待技术勘察。

## 6.2 视频来源

第一版目标来源：

- Bilibili
- YouTube
- 其他受支持的网页视频来源
- 本地视频导入

平台支持范围取决于 yt-dlp 版本、平台接口变化、用户访问权限和相关服务规则。

## 6.3 登录和账号

支持临时登录、长期授权及多个账号配置。

安全要求：

- 优先使用系统凭据存储。
- 尽量不持久化明文 Cookie 或访问令牌。
- 提供查看授权状态、撤销授权和清除凭据的入口。
- 下载任务记录不得直接包含可复用的明文登录凭据。
- 便携版必须单独评估凭据保护方式。

浏览器登录、Cookie 获取方式及多账号实现细节待技术勘察。

## 6.4 任务创建入口

支持两个入口：

1. 项目内下载：自动关联当前项目。
2. 全局下载中心：允许稍后分配项目。

支持网址输入、批量添加和本地视频导入。

## 6.5 下载队列

每个下载任务应记录：

- 任务 ID
- 来源平台及来源标识
- 原始网址
- 目标项目
- 目标路径
- 任务状态
- 进度
- 下载速度
- 重试次数
- 创建和更新时间
- 错误信息
- 输出文件信息

队列至少支持：

- 等待、下载中、成功、失败、已取消等状态。
- 并发控制。
- 批量添加。
- 进度、速度和可获得时的剩余时间展示。
- 取消任务。
- 失败重试。
- 下载任务持久化。

暂停和继续应根据 yt-dlp 的实际能力实现；不能将停止后重新开始误称为真正的断点续传。

## 6.6 文件归档

下载完成后按平台、系列或集数执行归档，并将输出文件注册为项目素材。

归档必须支持：

- 检查目标目录。
- 检测重复来源 ID 或内容。
- 提示用户跳过、覆盖或另存为新文件。
- 防止覆盖尚未确认的文件。
- 下载失败时保留任务记录。
- 归档完成后询问用户是否打开 Aeg。

封面优先从平台元数据或视频缩略图获取；提取失败时允许使用默认封面。

# 7. 数据存储与配置管理

## 7.1 数据归属

项目数据跟随项目目录，全局设置留在应用配置中。

项目配置至少包含项目 ID、元数据、目录规则、状态、封面引用及必要的项目历史信息。

全局配置可以包含：

- 界面偏好
- 全局目录模板
- 下载并发设置
- 更新设置
- 日志设置
- 其他全局偏好

## 7.2 数据存储方案

具体采用 JSON、SQLite 或混合方案尚未确定。

技术勘察应比较：

- 可读性
- 项目迁移能力
- 文件索引查询性能
- 大项目适用性
- 备份和恢复难度
- 数据结构升级成本
- 对便携版的适配程度

最终方案必须支持项目目录迁移和应用版本升级。

## 7.3 项目配置版本

项目配置应具备可识别的格式版本。

升级时应：

1. 识别当前配置版本。
2. 校验配置和相关文件。
3. 必要时备份旧配置。
4. 执行受控迁移。
5. 验证迁移结果。
6. 失败时保留旧配置并提示用户。

项目数据迁移不应默认修改视频或字幕原始文件。

---

# 8. 删除、撤销与备份恢复

## 8.1 删除策略

项目和普通文件分别配置删除策略。

操作至少区分：

- 仅从项目管理中移除。
- 移入回收站。
- 永久删除。

删除项目时应明确告知是否会影响磁盘文件。

危险操作必须确认，不能因为删除项目管理记录就自动删除所有素材。

## 8.2 操作历史和撤销

尽可能支持操作历史、撤销与恢复。

第一版应优先保障常见文件操作的可恢复性，例如重命名、移动和删除。

对跨磁盘移动、正在下载的文件及其他无法安全回滚的操作，应明确限制，不能承诺所有操作均可撤销。

## 8.3 备份

- 自动保存项目配置。
- 支持手动导出完整项目备份。
- 备份时清楚说明是否包含视频、字幕、缓存和其他大文件。
- 恢复前校验项目配置及文件状态。
- 备份恢复不得默认覆盖现有文件。

---

# 9. 异常恢复

应用重新启动时应：

1. 恢复项目索引。
2. 检查项目路径是否仍有效。
3. 检查未完成下载任务。
4. 检查目标文件和临时文件。
5. 判断任务是可以继续、需要重试还是需要用户处理。
6. 恢复上次使用的项目和相关页面提示。
7. 对无法确定的状态给出明确提示，而不是静默认定任务成功。

下载任务持久化与实际断点续传应作为两项独立能力进行验证。

# 10. 更新系统与版本策略

## 10.1 产品维护关系

该产品基于用户修改版 Aeg 发布。

开发维护流程应定期合并上游 Aeg 更新，同时保留自定义修改。

需要建立可审查的分支、提交和版本发布流程。实际分支策略、合并方式和构建流程必须以仓库勘察为准。

## 10.2 应用版本

对用户呈现一个明确的完整应用版本号。

版本应能够对应到：

- Aeg 上游基线。
- 自定义修改版的提交。
- 新增项目管理功能版本。
- 相关依赖版本。
- 发布说明。

以上信息的具体编码方式待技术勘察。

## 10.3 更新体验

用户选择的更新方式为：

1. 检查是否有新版本。
2. 通知用户并展示更新说明。
3. 用户确认后下载。
4. 用户确认后安装或升级。
5. 升级前保护用户配置和项目数据。
6. 安装或迁移失败时尽量恢复原有可用状态。

不得未经用户确认静默安装更新。

## 10.4 安装版与便携版

两种发布形式均应纳入更新设计。

安装版需要明确安装路径、更新权限和旧版本配置迁移方式。

便携版需要考虑目录可移动性、原地升级、程序文件替换及项目数据安全。

具体实现方式应在仓库勘察后决定。

## 10.5 更新验证

更新程序应验证下载文件的完整性和来源。

具体采用何种签名、校验机制和发布基础设施，属于待技术勘察及发布决策事项。

## 10.6 依赖更新

yt-dlp 和 FFmpeg 等外部工具应有独立的版本记录与更新策略。

优先复用系统已有工具，但应能识别缺失或不兼容的依赖，并向用户提供明确提示。

# 11. 安全、隐私与日志

## 11.1 禁止遥测

本产品不允许未经用户明确同意的遥测或自动上传运行数据。

第一版不应引入自动上传诊断信息的机制。

## 11.2 本地日志

记录必要的本地运行信息，包括：

- 应用运行错误
- 下载失败原因
- 任务状态变化
- 项目路径关联错误
- 文件操作失败

日志不得默认记录明文 Cookie、访问令牌或其他可复用凭据。

## 11.3 凭据安全

- 优先使用系统凭据存储。
- 尽量避免明文凭据落盘。
- 提供撤销和清除凭据功能。
- 不将可复用的凭据写入项目配置、普通日志或诊断信息。
- 便携版应明确说明凭据存储和跨设备迁移的限制。

## 11.4 文件安全

- 对危险操作进行确认。
- 对路径失效、路径冲突和文件占用进行校验。
- 不静默覆盖或删除。
- 对文件监测与下载并发产生的冲突进行处理。
- 恢复和升级前保护现有数据。

# 12. 技术架构约束

以下内容是产品约束，不是已经确定的实现方案。

## 12.1 平台

Windows 优先，架构尽可能兼顾 macOS 和 Linux。

## 12.2 UI 与核心集成

UI 技术及 C++ 集成方式由技术勘察决定。

在修改现有核心之前，必须分析：

- 现有模块依赖。
- UI 线程与后台任务机制。
- 编辑器窗口生命周期。
- 工程文件读写路径。
- 可能受到影响的原有功能。

核心修改方案需要经过确认。

## 12.3 后台任务

下载、文件监测、缩略图处理和目录扫描应尽量在后台执行，不能阻塞主 UI 线程。

## 12.4 进程与资源

- yt-dlp 使用独立子进程。
- 尽量避免不必要的常驻进程。
- 控制内存占用。
- 支持大量项目和大量文件。
- 不要求第一版在 Aeg 关闭后继续下载。

后续如需关闭 Aeg 后继续下载，可另行评估独立后台服务。

## 12.5 便携版

便携版必须作为正式交付目标设计，而非安装版完成后再临时打包。

必须验证其配置存储、项目迁移、凭据保护、外部依赖和更新机制。

# 13. 第一阶段与第二阶段范围

## 13.1 第一阶段：完整基础工作流

第一阶段以建立可靠的项目管理基础为目标。

### 项目管理

- 项目首页和左侧导航。
- 创建、导入和打开项目。
- 系列与子项目管理。
- 项目元数据及状态。
- 可配置目录模板。
- 项目仪表盘和文件管理器。
- 全局搜索。
- 项目移动与外部文件监测。
- 同窗口和独立窗口的编辑器联动。

### 下载

- yt-dlp 子进程集成。
- 支持目标平台及本地导入。
- 项目内和全局任务入口。
- 任务持久化。
- 并发控制、进度、速度、失败重试。
- 重复文件处理。
- 自动归档和素材注册。
- 登录凭据管理。

### 数据与安全

- 项目配置跟随目录。
- 全局设置独立保存。
- 配置备份和手动项目备份。
- 基础操作历史和可实现的撤销能力。
- 外部移动检测和路径重新关联。
- 本地日志。
- 无自动遥测。
- 基础异常恢复。

### 发布与更新

- 源码、安装版、便携版发布流程。
- 应用版本和更新说明。
- 更新检查与用户确认下载、安装。
- 项目配置版本管理和基础迁移。
- yt-dlp 等依赖版本记录。

## 13.2 第二阶段：异常与性能专项

用户已明确将异常测试和性能测试安排在第二阶段。

第二阶段重点包括：

- 断网、磁盘空间不足和强制退出的专项恢复测试。
- 文件被占用、并发移动、下载中删除等异常场景。
- 大量项目和大量文件下的性能测试。
- 高并发下载及长时间运行稳定性测试。
- 文件扫描和索引性能优化。
- 更完善的撤销、历史版本和恢复能力。
- 根据第一阶段反馈进一步完善 UI 和工作流。

第一阶段仍必须具备基本安全校验和可运行的测试，不能将基础安全保障推迟到第二阶段。

# 14. 第一阶段验收标准

以下为产品验收要求。具体数值性能门槛应在技术勘察和基准测试后确定，不应凭空指定。

## 14.1 项目功能

1. 能创建独立项目，并在指定目录生成项目配置。
2. 能注册已有目录，且不会未经确认移动其内容。
3. 能创建系列并添加独立子项目。
4. 能显示项目名称、状态、封面、路径和更新时间。
5. 能使用模板创建项目，并导入、导出模板。
6. 能在项目管理与现有编辑器之间切换。
7. 能搜索项目、系列、文件和下载任务。

## 14.2 文件管理

1. 支持基本文件操作及批量操作。
2. 外部新增、删除、重命名和修改能反映到项目页面。
3. 外部移动项目后能够重新关联。
4. 发生文件冲突时不会静默覆盖。
5. 项目移动后项目配置和字幕文件关联保持有效。

## 14.3 下载功能

1. 能创建项目内下载任务和全局下载任务。
2. yt-dlp 进程退出后，Aeg 能记录任务结果。
3. 能展示下载进度和速度。
4. 失败任务可以重试。
5. 下载完成后素材进入正确的项目归档目录。
6. 重复文件能触发规定的处理流程。
7. 下载完成后能提示用户是否打开 Aeg。
8. 应用重启后能重新检查未完成任务及其实际文件状态。

## 14.4 数据安全

1. 项目配置跟随项目目录。
2. 全局设置与项目配置相互独立。
3. 删除、覆盖等危险操作需要确认。
4. 项目配置支持备份和恢复。
5. 日志不包含明文 Cookie 或访问令牌。
6. 不存在未经用户明确同意的自动遥测或诊断上传。

## 14.5 兼容与发布

1. 原有字幕文件读写功能通过回归测试。
2. 现有编辑器基本行为不因项目管理功能而退化。
3. 安装版和便携版均可运行。
4. 项目配置迁移失败时不会静默破坏旧配置。
5. 更新提示、更新说明和用户确认流程符合要求。
6. 更新后仍能打开既有项目。

## 14.6 第一阶段测试范围

- 单元测试。
- 集成测试。
- 原有功能回归测试。
- 便携版测试。
- 安全测试。

第二阶段再集中进行更完整的异常测试与性能测试。

# 15. 待技术勘察清单

开始实施前，Agent 必须检查真实仓库，形成技术调查报告。

## 15.1 仓库与版本

- 确认仓库地址、分支、提交及当前自定义修改。
- 识别上游 Aeg 基线与自定义修改之间的差异。
- 了解现有分支策略和上游合并风险。

## 15.2 构建与 UI

- 检查 C++ 标准、构建系统和第三方依赖。
- 确认实际 UI 框架及其支持的页面、窗口和后台任务模式。
- 评估同窗口页面切换与独立编辑窗口的集成方式。
- 识别必须修改核心代码的部分。

## 15.3 数据与文件系统

- 检查现有设置、工程文件和配置存储机制。
- 比较 JSON、SQLite 或混合存储方案。
- 评估文件监测、目录移动、路径重新关联和大量文件索引。
- 设计项目配置版本与迁移机制。

## 15.4 下载器与凭据

- 验证 yt-dlp 的进程控制与输出解析方式。
- 检查 FFmpeg 等依赖的可用性和分发要求。
- 评估 Cookie、多账号及系统凭据存储。
- 明确下载任务持久化、退出和恢复行为。

## 15.5 安装、便携与更新

- 检查现有安装包生成流程。
- 检查便携版能力与配置目录策略。
- 确认用户数据和程序文件的分离方式。
- 评估更新包验证、版本检查、安装与失败恢复方案。
- 检查第三方依赖及许可证要求。

## 15.6 技术勘察输出

Agent 应交付：

1. 仓库现状报告。
2. 现有模块和依赖关系说明。
3. 候选技术方案比较。
4. 对现有核心代码的修改范围分析。
5. 风险清单及兼容性评估。
6. 建议的实施顺序。
7. 需要用户确认的技术决策。

在技术勘察完成且必要决策得到确认前，不应直接开始大规模重构或修改现有核心。

# 16. 最终交付定义

本项目的第一阶段完成标志，不只是新增一个项目管理页面，而是形成一个可以实际使用的完整工作流：

创建项目 → 导入或下载视频 → 自动归档 → 管理字幕素材 → 打开 Aeg 编辑 → 维护项目状态 → 备份与恢复 → 通过受控更新升级软件。

所有新功能都必须建立在对现有 Aeg 代码的充分理解之上，并保护原有字幕编辑能力、用户数据和自定义修改。

本 PRD 是后续技术勘察与实施的需求基线。技术选型、仓库现状和尚未确认的实现细节，必须通过实际调查和后续决策确定。
